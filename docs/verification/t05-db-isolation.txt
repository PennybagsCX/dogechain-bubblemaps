## Why the round-trip is at the Prisma layer, not literally via services/db.ts

$ grep -nE "from ['\"]dexie['\"]|PrismaClient|from ['\"]pg['\"]|@neondatabase" services/db.ts
3:import Dexie, { Table } from "dexie";

services/db.ts is a browser-side Dexie (IndexedDB) layer. Its only server path is
fetch("/api/alerts…") (syncAlertsToServer / syncAlertsFromServer), and the handlers that turn that
payload into user_alerts / triggered_alerts rows do not exist in this fork yet (card T-06).
`db-roundtrip.mjs` therefore exercises the storage layer those handlers will use, with the same row
shapes, and refuses to run against any non-loopback host.
